# Alconite Actions v2.5.0

This release removes mandatory GitHub artifact attestation from consumer image publication, expands the developer documentation, and fixes dependency, credential-handling, and Runtime Verify privacy issues. All Action entry points and reusable workflows share the v2.5.0 release identity.

## Features and documentation

- **Publish without GitHub artifact attestations.** Stack CI no longer requires the GitHub attestation service or `id-token: write` / `attestations: write`. Docker BuildKit SBOM and provenance metadata remain enabled in the stack publish job. The standalone Docker helper exposes those controls separately and defaults both to disabled. Alconite's own release pipeline continues to attest its distributions and Sentinel image.
- **Complete helper references.** Each helper now documents prerequisites, inputs, outputs, credentials, permissions, examples, and troubleshooting: [Java CI](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/java-ci.md), [Java Publish](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/java-publish.md), [Node CI](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/node-ci.md), [Rust CI](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/rust-ci.md), [Docker CI](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/docker-ci.md), and [Discord Notify](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/discord-notify.md).
- **A clearer path into Alconite.** New [getting started](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/getting-started.md), [Stack CI](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/stack-ci.md), [troubleshooting](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/troubleshooting.md), and [versioning](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/versioning.md) guides cover Contract Guard → Impact → deployment → Runtime Verify, enterprise compatibility, token scopes, and version or immutable SHA adoption.
- **Verified release references.** The downloadable `release-pins.md` and `release-pins.json` assets resolve the actual release tag to a full commit SHA for all eleven Action and reusable-workflow entry points. This release also includes the Sentinel image digest and its SPDX JSON SBOM.

## Security fixes and upgrades

- **Prevent target credential forwarding outside the configured origin.** Runtime Verify rejects ambiguous operation authorities, backslashes, control characters, and other paths that would escape the target origin before making a request. The existing cross-origin redirect restriction remains in place.
- **Keep response-owned data out of findings.** Runtime Verify uses schema-owned locations instead of dynamic response keys, excludes unexpected response media-type values from evidence, and redacts configured credentials before computing result identities. Target response bodies remain on the runner.
- **Withhold private dependency tokens on all pull requests.** Stack CI's Java and Node builds receive no private package token for either fork or same-repository `pull_request` events.
- **Upgrade vulnerable dependencies and regenerate distributions.** Updates include `fast-uri` 3.1.7, Swagger Parser 13.0.0 and its reference resolver, and `ignore` 7.0.8. The release also refreshes esbuild, Node type definitions, reviewed Docker Buildx/QEMU, CodeQL SARIF upload, pnpm setup, Rust cache Action pins, and the pinned Sentinel runtime image.
- **Pin internal helper calls.** All eight reusable-workflow component calls use the reviewed full commit SHA recorded in `release-components.json`. Release validation requires that commit to remain in history and verifies that its Action content and build inputs match the release.
- **Maintain dependency monitoring.** Dependabot now monitors the Sentinel Dockerfile weekly alongside npm and GitHub Actions. Automatic security-update pull requests are enabled.

The [security maintenance report](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/security-maintenance.md) records the reported repository alerts and their remediations. GitHub alert status depends on analysis of the merged default branch; these notes do not imply that every alert has closed.

## Upgrading

1. Update Action and reusable-workflow references to `v2.5.0`, or use the matching full SHA examples generated below. Use the image digest separately when pinning Sentinel.
2. Remove `id-token: write` and `attestations: write` from consumer workflows when no other step needs them. Start ordinary checkout/build/test and direct Alconite jobs with `contents: read`; grant `packages: write` only for GitHub Packages/GHCR publication and the other permissions required by your chosen workflow.
3. If your organization requires GitHub artifact attestations on a supported GitHub plan, compose the Docker helper with the [documented optional attestation step](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/helpers/docker-ci.md#optional-add-github-attestation-on-a-supported-plan). For a registry that rejects BuildKit metadata, use the standalone Docker helper with `sbom` and `provenance` disabled.
4. If PR builds require private Java or Node dependencies, arrange a separate trusted build after code review. The stack intentionally withholds those credentials on every PR event. Check the [enterprise guidance](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/troubleshooting.md#enterprise-environments-and-attestations) for runner and GitHub Enterprise Server requirements.

Existing Action inputs and outputs are unchanged. Publishing this release does not deploy or enable Alconite platform features.

## Known limitation

The September 8, 2026 security review found no High or Critical findings in the refreshed Sentinel image. One **Medium** finding remains: **CVE-2026-18374 / GLIBC-SA-2026-0015** in `glibc` 2.44-r5, pending a vendor package containing the upstream fix. No suppression was added; the release image scan continues to fail on High or Critical findings, including unfixed ones. See the [advisory, upstream fix, and remediation tracking](https://github.com/alconite-inc/alconite-actions/blob/v2.5.0/docs/security-maintenance.md#container-scan-and-remaining-upstream-finding).

The image SBOM inventories operating-system packages and the copied Node binary. Bundled JavaScript does not include npm package manifests, so the production lockfile scan and npm audit provide the separate npm dependency coverage.
